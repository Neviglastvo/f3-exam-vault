# Web програмування

> [!summary] Відповідь за 20–30 секунд
> Web-застосунок зазвичай працює за клієнт-серверною моделлю: браузер надсилає [[Глосарій#HTTP|HTTP]]-запит, сервер перевіряє його, виконує прикладну логіку, за потреби працює з БД і повертає відповідь. [[Глосарій#HTML|HTML]] описує структуру, [[Глосарій#CSS|CSS]] — подання, JavaScript — поведінку в браузері.

## Суть
- [[Глосарій#URL|URL]] і [[Глосарій#DNS|DNS]] визначають ресурс і перетворюють ім'я на мережеву адресу; [[Глосарій#HTTP|HTTP]] описує запити, методи, заголовки, коди стану й тіла повідомлень. [[Глосарій#HTTPS|HTTPS]] додає захищений транспорт через [[Глосарій#TLS|TLS]].
- Frontend виконується у браузері, backend — на сервері; [[Глосарій#API|API]] задає контракт обміну. Дані часто передають у JSON, але формат є частиною контракту, а не властивістю вебу.
- Архітектура відокремлює маршрутизацію, автентифікацію/авторизацію, прикладну логіку, доступ до даних, кешування, журналювання й обробку помилок.
- Базові принципи: перевіряти вхід на сервері, застосовувати найменші привілеї, не довіряти даним клієнта, захищати сесії й секрети, обробляти помилки без витоку чутливих даних.

## Іспитовий фокус
- **Що запам'ятати:** HTTP є протоколом прикладного рівня; браузер — лише один із можливих клієнтів API.
- **Типова пастка:** клієнтська валідація покращує зручність, але не є захистом, бо запит можна сформувати без інтерфейсу.
- **Можливі питання:** «Принципи web-програмування». «Опишіть запит від браузера до БД і назад».

## Самоперевірка
- **Поясни без нотатки:** компоненти шляху HTTP-запиту до веб-API.
- **Назви 2–3 ключові поняття або кроки:** URL, HTTP, сервер, API, БД.
- **Порівняй із найближчою пов’язаною темою:** frontend і backend.
