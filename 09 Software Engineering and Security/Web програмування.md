# Web програмування

## Конспект розгорнутої відповіді

- Вебзастосунок складається щонайменше з клієнта, який формує HTTP-запит, і сервера, який обробляє його та повертає відповідь. Клієнтський код працює в браузері, серверний — на сервері; це розподіл ролей, а не набір конкретних мов.
- HTTP-запит містить метод, ціль, заголовки та за потреби тіло; відповідь — статус, заголовки й тіло. Методи `GET`, `POST`, `PUT`, `PATCH`, `DELETE` мають різну семантику; назва методу сама по собі не робить операцію безпечною.
- HTML задає структуру й зміст документа, CSS — подання, JavaScript — поведінку в браузері. DOM — об'єктна модель документа, через яку сценарій читає та змінює сторінку.
- Сервер зазвичай реалізує маршрути, перевірку введення, автентифікацію, авторизацію, доступ до даних і журналювання. Клієнт не є довіреною стороною: сервер повторно перевіряє права й дані.
- Мінімальна безпека: TLS для передавання, валідація на сервері, параметризовані запити до БД, захист сесії, кодування даних у HTML-контексті та контроль доступу. «Захист на фронтенді» не замінює серверної перевірки.
- Вебмови й технології обирають за роллю: HTML і CSS задають документ та подання, JavaScript або TypeScript часто виконують клієнтську логіку; серверну частину можна реалізувати різними мовами. Перевагу визначають вимоги, бібліотеки, команда й середовище розгортання, а не сама назва мови.
- **Перевірка:** [[Перевірені джерела для ІПММС#Програмування, web і безпека]].

> [!summary] Відповідь за 20–30 секунд
> Web-застосунок зазвичай працює за клієнт-серверною моделлю: браузер надсилає [[Глосарій#HTTP|HTTP]]-запит, сервер перевіряє його, виконує прикладну логіку, за потреби працює з БД і повертає відповідь. [[Глосарій#HTML|HTML]] описує структуру, [[Глосарій#CSS|CSS]] — подання, JavaScript — поведінку в браузері.

## Суть
- [[Глосарій#URL|URL]] і [[Глосарій#DNS|DNS]] визначають ресурс і перетворюють ім'я на мережеву адресу; [[Глосарій#HTTP|HTTP]] описує запити, методи, заголовки, коди стану й тіла повідомлень. [[Глосарій#HTTPS|HTTPS]] додає захищений транспорт через [[Глосарій#TLS|TLS]].
- Frontend виконується у браузері, backend — на сервері; [[Глосарій#API|API]] задає контракт обміну. Дані часто передають у JSON, але формат є частиною контракту, а не властивістю вебу.
- Архітектура відокремлює маршрутизацію, автентифікацію/авторизацію, прикладну логіку, доступ до даних, кешування, журналювання й обробку помилок.
- Базові принципи: перевіряти вхід на сервері, застосовувати найменші привілеї, не довіряти даним клієнта, захищати сесії й секрети, обробляти помилки без витоку чутливих даних.

## Іспитовий фокус
- **Що запам'ятати:** HTTP є протоколом прикладного рівня; браузер — лише один із можливих клієнтів API.
- **Типова пастка:** клієнтська валідація покращує зручність, але не є захистом, бо запит можна сформувати без інтерфейсу.
- **Розгорнута відповідь:** конспект вище пояснює шлях HTTP-запиту, ролі клієнта й сервера, вебстандарти та межу безпеки.
