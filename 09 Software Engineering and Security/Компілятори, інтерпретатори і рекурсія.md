# Компілятори, інтерпретатори і рекурсія

> [!summary] Відповідь за 20–30 секунд
> Компілятор аналізує вихідний код і перекладає його в іншу форму до виконання або для подальшого виконання; інтерпретатор виконує програму через проміжне подання чи безпосередньо. Рекурсивна функція викликає себе для меншої підзадачі й мусить мати базовий випадок.

## Суть
- Етапи компіляції: лексичний аналіз → синтаксичний аналіз → семантичний аналіз і перевірка типів → проміжне подання → оптимізація → генерація коду/зв'язування. Реальні системи можуть поєднувати ці етапи.
- Інтерпретатор зручний для інтерактивного запуску й переносимості, але конкретна продуктивність залежить від реалізації: байткод, [[Глосарій#JIT|JIT]]-компіляція й кешування стирають просте протиставлення.
- Рекурсія коректна, коли задача розкладається на менші екземпляри й є базовий випадок. Глибока рекурсія витрачає стек; іноді її замінюють явним стеком або циклом.
- Рекурсивні алгоритми природні для дерев, графів, divide-and-conquer і рекурентних визначень, але треба аналізувати складність і дублювання підзадач.

## Іспитовий фокус
- **Що запам'ятати:** компілятор та інтерпретатор — способи реалізації мови, а не взаємовиключні властивості самої мови.
- **Типова пастка:** рекурсивний виклик без базового випадку або без зменшення задачі веде до нескінченної рекурсії/переповнення стека.
- **Можливі питання:** «Призначення компілятора й інтерпретатора». «Які умови коректної рекурсії?»
